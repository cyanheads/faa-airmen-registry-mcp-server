# 0.2.0 — 2026-10-21

## Added

- **`FAA_AIRMEN_REDACT_PII`** is on by default and applied at serving time; only `false` turns it off ([#17](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/17)). Every success of all six tools carries `piiRedacted`.
- **`nameMatch: "words"`** matches each supplied name field's whole leading words (`JOHN` finds `JOHN ROBERT`, `SMITH` finds `SMITH JR`, not `SMITHSON` or `SMITH-JONES`) ([#7](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/7)).
- **`faa_airmen_verify_certificate`** takes `certificateLevel`, `ratingCodes`, and `typeRatings`, all required on one certificate ([#13](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/13)).
- **`prune`** command in `faa-airmen-registry-mirror` deletes every generation `CURRENT` does not name; CLI `status` reports their count and size. Stop every server process first ([#14](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/14)).
- **`lastRefreshFailure`** reports `cancelled` for a stopped caller, `timeout` for an expired deadline, and `interrupted` for a refresh record older than the 40-minute deadline, which `mirror_status` shows as `refreshState: "failed"` instead of `running` ([#15](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/15), [#18](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/18)).
- **`SUAS`** rating is described from 14 CFR 107.12; the source-quality notice now appears only when a returned record carries an undocumented code or malformed value ([#9](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/9)).
- **CFII and MEI** rating codes are named in `ratings` guidance and the instructor `ratingCodes` description ([#10](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/10)).

## Changed

- **Per-call `provenance` drops twelve fields** on all six tools: `archiveUrl`, `complete`, `counts`, `downloadedAt`, `fileCounts`, `importedAt`, `publishedAt`, `referenceVersion`, `schemaVersion`, `sha256`, `sourcePageUrl`, and `warnings`. They remain in `faa_airmen_list_reference` topic `mirror_status`; `tools/list` shrinks 81,738 B → 74,208 B (−9.2%) ([#12](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/12)).
- **Default redaction rejects calls that used to succeed**, with reason `pii_redacted`: every `faa_airmen_check_medical_status` call, name searches without both `lastName` and `firstName`, `nameMatch: "prefix"`, and `city`/`zipCode` filters; city and ZIP are omitted from output. Set `FAA_AIRMEN_REDACT_PII=false` to restore the previous surface ([#17](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/17)).
- **`nameMatch` defaults to `words`** instead of `exact`; results are a superset, and `exact` and `prefix` remain explicit ([#7](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/7)).
- **Validation errors name the field** and give a field-specific recovery. `certificateType` accepts the topic descriptions (`remote pilot`), `ratingCodes` accepts `level/code` and collapses repeats, and `limit` above 50 clamps to 50 with a notice ([#11](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/11)).
- **Malformed `uniqueId` or `zipCode`** now fails the input schema with `invalid_arguments` instead of a service `invalid_identity` or `invalid_filter` ([#11](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/11)).
- **Zero-result notices** route by the filters sent and never suggest dropping a required name ([#10](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/10)).
- **Prefix and state predicates** use index ranges, and generations imported after this release index first names for first-name-only instructor searches; existing generations still serve unindexed until `refresh` ([#8](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/8), [#20](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/20)).
- **CLI configuration errors** print the framework message naming the variable ([#19](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/19)).

## Fixed

- **Default mirror directory** ignores a blank or relative `XDG_DATA_HOME` or `LOCALAPPDATA` instead of anchoring at the working directory, and fails naming `FAA_AIRMEN_MIRROR_DIR` when no absolute home exists ([#16](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/16)).
- **Refresh failure stages** record the phase that failed: an unparseable archive link is `acquisition` and SQLite storage errors are `disk` ([#15](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/15)).
- **`WRITER.lock` release** removes only the lock the writer created ([#21](https://github.com/cyanheads/faa-airmen-registry-mcp-server/issues/21)).
